## Failing or blocked requirements

- Live LLM activation: FAIL. The running backend returned `llm_analysis.status=disabled` and `evidence_analysis.status=disabled`; the diagnostic returned NOT_CONFIGURED, model=null. No OpenAI call, live structured response, or live semantic-quality validation occurred.
- Semantic Scholar live retrieval: FAIL for this audit. The isolated probe returned RATE_LIMITED with zero accepted papers. Other providers supplied partial results.
- Strict immutable historical presentation: NOT SATISFIED by architecture. `serialize_run` calls `canonical_result`, which re-synthesizes report presentation using current code. Raw snapshots remain unchanged, but rendered reports can change after a release without explicit regeneration. Older intelligence can also be adapted while separate module snapshots remain unchanged.
- Narrow viewport layout: observed horizontal overflow/clipped toolbar controls in the headless browser screenshot. Main flows passed, but responsive usability needs a targeted fix.

## Research quality and limitations

The browser healthcare run retained 47 passages, 2 deterministic findings and 1 reported gap. Four additional live runs with the objective “Compare methods and evaluation evidence” each retained 21 passages but produced zero findings and zero gaps. Empty output was not filled with invented claims. This demonstrates that retrieval is working while deterministic analysis still misses useful content or lacks sufficient extractable support.

The saved-fixture semantic test produced 2 exact findings and 1 inferred candidate gap from 30 passages, but used a mocked LLM. It does not prove model quality in production. Model confidence, lexical overlap and numeric checks do not establish entailment. Recommendations remain partly templated; course coverage is only two verified foundational MIT courses; dataset matches still require suitability/license review.

## Security

Live checks: anonymous history/research submission 401; signed-out history 401; cross-user research, intelligence and PDF read 404; cross-user intelligence generation 404; missing-CSRF submission 403. Browser signup/signin/signout succeeded. Code uses backend credentials, opaque sessions, HttpOnly cookies and Argon2 password hashing. No OpenAI-style key strings were found in the generated frontend bundle. No API key is configured, so this is not a proof of secret handling under every future deployment configuration.

No access-control bypass was found in the tested flows. This was not a penetration test. Local HTTP/development settings must not be treated as verified production HTTPS/cookie configuration.

## Recommended fixes, in order

1. Configure an accessible OpenAI model and server-only credentials; pass the diagnostic, then repeat live grounding/fallback/usage tests. Do not label deterministic runs as LLM-enhanced.
2. Establish model quality with blinded source-grounding examples, including negative cases and comparable/opposing studies. Keep uncertain synthesis separate from established findings.
3. Address Semantic Scholar access/rate limits; preserve fallback and expose provider failures.
4. Version canonical presentation snapshots and offer explicit regeneration so historical report and module views stay consistent.
5. Broaden verified resource coverage and measure recommendation relevance beyond template differences.
6. Fix narrow-screen toolbar overflow without redesigning the interface.
7. Before production scaling, replace in-process background execution and throttles with durable jobs/shared limits; run concurrency and recovery tests.
